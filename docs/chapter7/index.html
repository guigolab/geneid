Chapter 7

RNA-seq & homology evidence

-S feeds geneid a per-base signal that scores exons — either protein-homology alignments or RNA‑seq coverage. -Y uses a BAM as both coverage and junctions.

The -S option supplies a signal that raises the score of exons it overlaps. It accepts two kinds of evidence: protein homology as HSP alignments, and RNA‑seq coverage as bigWig or BAM. The rest of this chapter covers each.

Protein homology (HSPs)

Given alignments between the input and well-annotated sequences, the High-scoring Segment Pairs (HSPs) can raise the score of overlapping predicted exons. Supply them as a GFF list with -S; order does not matter. To combine several alignments, geneid projects the HSPs onto the sequence, taking the highest score at each position. Positions with no homology get the parameter file's NO_SCORE value (chapter 8).

Frame in BLAST vs geneid BLAST frames are 1,2,3 (from start mod 3, with 0 → 3); geneid frames are 0,1,2 (nucleotides to the first complete codon). geneid converts between them internally as blastFrame = (start(exon) + geneidFrame) mod 3. Give a frame of . for DNA–DNA alignments, which have none.

RNA-seq coverage

RNA‑seq read depth scores exons by expression. Supply it as stranded or unstranded bigWig, or — in an htslib build — directly as an indexed BAM:

$ bin/geneid -3U -u -y rf -S plus.bw,minus.bw  -P param/human.rnaseq.param genome.fa
$ bin/geneid -3U -u -y rf -S reads.bam         -P param/human.rnaseq.param genome.fa

Coverage scores exons with or without -u; adding -u also predicts UTRs from where coverage extends beyond the coding exons. -y sets library strandedness (rf = dUTP/reverse, the common Illumina protocol; fr; or none). BAMs must be coordinate-sorted and indexed.

Expression scoring (-L / -Q)

By default the coverage term is additive and has no null model, so background transcription is rewarded and the score grows with sequencing depth — deep libraries over-predict. -L replaces it with a two-state log-likelihood ratio against the sequence's own background coverage: a base scores positive only where it is genuinely enriched over that background, and only its fold-enrichment matters, so the score does not drift with library size.

FlagMeaning
-L <k>Enable expression LLR scoring. k is the enrichment of an expressed exon over the genome-wide mean coverage (tens, not units, because most of a genome is untranscribed). Off by default.
-Q <w>Weight of the -L term against the coding/site scores (default 0.0007). It transfers across library depths but depends on the parameter file's factors, so re-tune it if you change parameter files.
Recommended start For human RNA‑seq: -L 50 -Q 0.0007 together with -u.

Multiple libraries (-Y a.bam,b.bam,… and -K)

-Y takes a comma-separated list of BAMs to combine several libraries in one run — each also contributes its junctions. They are not merged: each library keeps its own background estimate (which reflects tissue biology, not just depth, and varies several-fold per read across tissues), and their per-base scores are combined by an order statistic. Junctions are unioned across libraries with read support summed.

FlagMeaning
-K <n>How many libraries must support a base for it to count as expressed (default 2; 1 = the plain maximum / union). Requiring two suppresses single-library noise, whose false positives would otherwise grow with the number of libraries. A single BAM ignores -K.
-I <n>Minimum reads (summed across all libraries) supporting a BAM junction before it becomes intron evidence (default 1). -I 2 helps a little for a single library; it is redundant once -K ≥ 2.
-N <M>Millions of reads mapped, used only for the rpkm= report attribute; estimated from a BAM index when omitted.
How many tissues? Diminishing returns set in around four diverse tissues: on a human benchmark, most protein-coding genes reachable from RNA‑seq are covered by the fourth complementary library, and adding more (or a second sample of the same organ) helps little. Prefer complementary tissues over many similar ones.

One BAM, both roles (-Y)

A single -Y reads.bam uses that BAM as both the -R junction source and the -S coverage source, instead of passing it to each separately. A full example — GFF3 output, U12 introns allowed, UTRs, expression scoring, from one STAR/minimap2 BAM:

$ bin/geneid -3U -u -y rf -L 50 -Q 0.0007 -Y aligned.bam \
             -P param/human.rnaseq.param genome.fa

And several tissue BAMs, each keeping its own background, two required to agree:

$ bin/geneid -3U -u -y rf -L 50 -Q 0.0007 -K 2 \
             -Y brain.bam,liver.bam,heart.bam,testis.bam \
             -P param/human.rnaseq.param genome.fa
Hard-mask repeats geneid ignores soft-masking. Hard-mask repeats to N in the FASTA; otherwise repeat-region coverage inflates false predictions (chapter 4).
