Chapter 3

Installing geneid

geneid builds from source with a single make. A plain build needs only a C compiler and zlib.

Get the source

$ git clone https://github.com/guigolab/geneid.git
$ cd geneid

Or download a release tarball from the releases page and unpack it.

Build

$ make

This produces the executable at bin/geneid. Test it:

$ bin/geneid -h
Memory geneid's working arrays grow on demand, so there is nothing to size at build time — just make. (The old MEM=low|medium|high build profiles are gone.) Resident memory follows the input and stays modest, a few GB even on a large, dense genome.

Dependencies

zlib — required

Used by the indexed bigBed (-R) and bigWig (-S) readers. It is preinstalled on virtually every system (package zlib1g-dev / zlib-devel); the Makefile links it with -lz automatically, so a plain make just works.

htslib — optional (for BAM input)

Reading indexed BAM evidence directly (-R/-S/-Y with a .bam) needs htslib. Enable it:

$ make WITH_HTSLIB=1

If htslib is not under /usr/local, point the build at its prefix:

$ make WITH_HTSLIB=1 HTSLIB_PREFIX=/opt/homebrew        # macOS / Homebrew
$ make WITH_HTSLIB=1 HTSLIB_PREFIX=/path/to/htslib

The build bakes HTSLIB_PREFIX/lib into the binary's runtime search path (-Wl,-rpath), so the resulting geneid finds libhts on its own — no module load or LD_LIBRARY_PATH at run time. Install htslib with brew install htslib, apt-get install libhts-dev, a cluster module, or from source.

Note The default build (plain make) never references htslib; BAM input simply is not available in that binary. bigWig / bigBed / GFF evidence still work without it.
